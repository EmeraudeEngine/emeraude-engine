# Engine Rules (emeraude-engine)

> Distilled from `dependencies/emeraude-engine/AGENTS.md` (§ Core Axioms) and the subsystem AGENTS.md files. They are authoritative.

- ⚠️⚠️ **THE WORLD CONVENTION IS Y-UP** (`+X` right, **`+Y` UP**, `+Z` back, forward `-Z`) — the
  glTF/USD/FBX convention, so scene imports are the **identity**. Gravity is a **vector** toward `-Y`
  (`EnvironmentPhysicalProperties::DownDirection`), never a signed scalar.
  **The engine was Y-DOWN until Aug 2026**, when the flip landed: Y is negated in the projection
  (`[Col1Row1] = -a`) and every local compensation the old mirror had accumulated was **deleted** —
  the loader winding swaps, the consumer's 180° X rotation, `AxisFlip`/`swapX/Y/Z`, the negative-axis
  gizmo arrows, the cubemap Y negations. **Never reintroduce any of them.** ⚠️ A comment saying the
  engine *is* Y-down is stale — fix it. A comment saying a compensation *belonged to* the Y-down era
  and is gone is deliberate memory — keep it. Read
  `dependencies/emeraude-engine/docs/coordinate-system.md` before touching any axis sign.
- **Vulkan-only, never a direct Vulkan call** outside `src/Vulkan/` — go through the `Graphics/` abstractions. GPU memory via **VMA**, CPU via **RAII**, no raw pointers.
- **Every GPU buffer (SSBO/UBO) updated per frame MUST be double-buffered** (one copy per frame-in-flight). Post-effects reconstructing world position read `viewMatrix(readStateIndex, ...)`, not the default overload.
- **Fail-safe resources**: loading **never returns nullptr** — fall back to a neutral resource.
- **`getOrCreateResource()` runs its factory lambda on the THREAD POOL**: captures **by value** only (never a raw `this`, never a reference to a caller temporary).
- **Multi-scene ownership**: a resource shared across scenes or outliving one (samplers, pipelines, programs, layouts, bindless table, AS builder, default textures) is owned **ONCE** at the Renderer/device level — never per scene, never in a global `static`. Read `docs/multi-scene-resource-ownership.md` before writing any resource code.
- Deferred Vulkan destruction via `Vulkan::DeferredDestructor` (mandatory); `Device::waitTransferQueuesIdle()` where required.
- Async TLAS: `prepareTLAS()` + `recordTLASBuild()`; barrier `FRAGMENT|COMPUTE` (ray queries), **never** `RAY_TRACING_SHADER_BIT`.
- New `VkFormat` ⇒ update `Image::pixelBytes()` **AND** `Image::colorCount()` (a missing case returns 0 and silently breaks multi-layer uploads).
- Push constants: min-spec is **128 bytes** — do not exceed without a guard.
- **ONE concrete material** since Aug 2026: `Material::StandardResource` (Cook-Torrance metallic-roughness). `BasicResource`, the legacy Blinn-Phong `StandardResource` and the whole per-vertex/Phong machinery are DELETED; `Material::Interface` is only the extension contract for future, structurally different shading models. There is no shader-quality SETTING either — the tier is a rendering decision on `Generator::Abstract::HighQualityEnabled`, meant to follow rendering DISTANCE.
- **Asset lights (`SceneDataConsumer::attachLight`, 2026-09-13)**: a directional light aims along its node's -Z (`useDirectionVector(true)`, KHR_lights_punctual/UsdLux); `intensity <= 0` is NOT instantiated (a 0 cd point light = unbounded culling radius); the shadow policy is the caller's `setDirectionalLightShadows(DirectionalShadowOptions)` — the SAME struct `BackgroundLightingOptions::shadows` carries for a sky's stars (`Scenes/DirectionalShadowOptions.hpp`, one dispatch `build()`). Exporters ship lights at 0 (Intel Sponza): fix the DATA with `tools/gltf-lights.py`.
- **Animated sun (`Component::SunCourse` + `Toolkit::generateSunCourse(name, SunCourse::Options, DirectionalShadowOptions)`, 2026-09-13)**: a movable pivot Node whose POSITION is the unit vector toward the sun (light in position-to-origin mode, `useDirectionVector(false)`), great circle sunrise → noon (`noonElevation`) → sunset at constant angular speed, day = night = `dayDuration` (120 s); illuminance = `zenithIlluminance · exp(−extinction·(airMass−1))` with the Kasten & Young 1989 air mass, colour temperature 5800 K → 2000 K with the same air mass, light DISABLED below the horizon. ⚠️ The SUN ONLY: sky, ambient and IBL stay the background's. ⚠️ Phase = INTEGER cycle counter over an integer revolution (owner rule: no float accumulation). Pivot = direct child of the root (world `setPosition()` complete only there).
- **Material dynamic properties are flushed by the Renderer** (2026-09-13): `StandardResource::set*Value()`/`setRoughness()`/… call `markVideoMemoryDirty()` → `Renderer::requestMaterialVideoMemoryUpdate()` → `flushMaterialVideoMemoryUpdates()` once per frame on the render thread (`Material::Interface::updateVideoMemory()` is virtual). Before, the 39 setters raised a flag nobody consumed: a material never changed on the GPU after `create()`. ⚠️ One frame region: a value may land one frame early. A "dynamic" flag needs a consumer — grep it.
- **`Component::SkyFollowsSun`** (2026-09-13): bound to a `SunCourse`, scales the scene background's luminance by a smoothstep of the elevation (−6° → 0, +10° → 1, `nightFactor`), then `Scene::refreshAmbientLightProperties()` — ONE knob for the IBL scale, the sky term and, via the new `AbstractBackground::onLuminanceChanged()` hook, the drawn skybox emission (`StandardResource::setEmissiveStrengthValue()`). Deliberately NOT part of `generateSunCourse()`: the demo composes the two.
- **A component may move or query its OWN entity from `processLogics()`** (2026-09-13): `m_componentsMutex` is RECURSIVE (same-thread re-entry legal by construction — it deadlocked the logic thread before: black frame, console alive, `Core.shutdown()` never completing), and `onContainerMove()` called from the component loop still DEFERS the `move()` dispatch to after the loop (same cycle, no mid-iteration move). FORBIDDEN from the loop: `linkComponent()`/`removeComponent()`/`clearComponents()` (traced error, no-op — a component leaves via `shouldBeRemoved()`).
- **A light tracks its frame while DISABLED** (2026-09-13): `DirectionalLight/PointLight/SpotLight::move()` no longer return early on `!isEnabled()` (a light switched on later kept a stale direction/shadow frame/matrix); the render passes skip disabled lights themselves. `DirectionalLight::resolveDirection()` falls back to the forward axis for a light AT the origin in position mode (a normalised null position = NaN in the light buffer).
- **`InTexture` is STRUCTURING**: the brightest in-texture star of a sky manifest is masked out of the IBL bake (`Scene::environmentStarMask()` → `IBLBaker::StarMask`, GLSL `maskStar()`, cone = one angular diameter widened by the sampled mip footprint); the analytic star carries the energy WITH shadows. ⚠️ Manifest `Direction` = TOWARD the body, UP = +Y; every store body measured in its picture on 2026-09-25 (`tools/sky-manifest.py --locate`: an LDR sun is a clipped PLATEAU — take its largest inscribed disc, not a centroid; a moon is an unclipped disc; a veiled sun anchors on the sky, `--sky-luminance`). The mask follows the manifest even with `applyStars = false`. Author a sky manifest with `tools/sky-manifest.py`, never by hand.
- **A ray-query operand is checked FINITE before `rayQueryInitializeEXT()`**: a NaN origin (degenerate hit normal → `normalize(0)`) is a DEVICE LOSS on NVIDIA, multiplied by every shadow ray. `getHitNormal()` returns `vec3(0)` on degeneracy, the caller falls back to the ray-facing direction, `shadowRayVisibility()` answers unoccluded to a non-finite ray. Run GPU-assisted validation (`VK_KHRONOS_VALIDATION_GPUAV_ENABLE=1`) before bisecting a device loss that "depends on a count".
- ⚠️⚠️ **A visual states its LIGHTING (2026-09-25, owner decision)**: `Component::Visual` / `MultipleVisuals` take `Graphics::RenderableInstance::Lighting::Lit|Unlit` as a REQUIRED last constructor argument. The former unlit default wrote raw albedo as radiance (black) with a constant (0,0,1) G-buffer normal: it struck BasicScenery, the USD InstanceCluster, then EVERY tree of `terrain`/`forest` (+ the imposter bake rig), lit by SSGI/RTGI alone — the GI hides an unlit mesh: test with `disable("IndirectDiffuse")`. Lighting the forest costs ~45 ms (lit lists drawn per batch, outside MDI: item `lit-lists-drawn-per-batch-without-mdi`); the owner: "the visual result comes before the performance". A lighting input the fragment reads must be requested for the vertex stage by the SAME condition (the bake had no vertex colour: every far tree vanished).
- **Volumetric clouds are ENTITIES (2026-09-24)**: `Toolkit::generateCloud(name, CloudShapeResource::Parameters, width, look)` = a NON-collidable entity + `Component::CloudVolume`; the scene files it in `Scenes::CloudSet`, and `PostProcessStack::syncSceneEffects()` files the `VolumetricClouds` pass (`EffectSlot::Clouds`, before `Fog`) the first frame a cloud exists — an application NEVER adds it (`Clouds/Enabled = false` declines it). ⚠️ Scaling a cloud KEEPS ITS LOOK: `Look::opticalThickness` is a vertical optical depth, the extinction is recomputed from the published height each frame. ⚠️ The shape is a DOME grown by `CloudShapeResource` (a sphere-only growth filled 5-8 % of its box). The pass traces a census (`Clouds drawn: N of M (...)`) when it changes — no line = `execute()` never ran. **Stage 2 lot 1 (2026-09-24): the clouds SHADOW the lit materials** — `Graphics::CloudShadowMap` (Beer shadow map: front depth / mean extinction / optical depth), owned by `Scenes::CloudSet`, recorded before the scene pass; the MAIN sun CARRIES it (owner decision: `cloudShadowMatrix` + `cloudShadowIndex` in the directional light block, `DirectionalLight::updateCloudShadow()` from `Scene::updateCloudShadows()`, frame snapped to the texel grid); the lookup is a UNIFORM BRANCH inside every PBR directional variant — no new `RenderPassType` (the variants are precompiled per renderable). ⚠️ The directional light block now ALWAYS declares its full layout; the C++ offsets (`CloudShadowMatrixOffset` 32 / 84 CSM) must stay in lockstep with `LightGenerator`. Both passes read ONE cloud description, `Effects/Shared/CloudVolumeGLSL.hpp`. **The god rays and the lens flare see the clouds (2026-09-24, owner: per-pixel transmittance)**: the cloud pass writes its view transmittance to a second render target (`VC_Transmittance`, R16F, MRT pass), `PostProcessStack::syncSlotPairings(clouds)` hands it every frame to the enabled `VolumetricLight` and `LensFlare` (protocol `cloudTransmittanceTexture()` / `consumesCloudTransmittance()` / `setCloudTransmittanceSource()`), `EffectSlot::VolumetricLight` moved AFTER `Clouds`. ⚠️ The producer never early-outs on 0 clouds drawn (it writes T = 1) and the pairing exists only while the scene holds clouds: a consumer never reads an unwritten image. A future depth-based visibility effect must consume it too. Not yet: `VolumetricScattering`, cloud-to-cloud, RT lanes (not in the TLAS). Engine `src/Graphics/AGENTS.md` § VolumetricClouds + § *The clouds' shadow on the world*, item `docs/todo/volumetric-cloud-entities.md`.
- ⚠️ **Cloud distance LOD (2026-09-25)**: past one base step the view step grows to 2 base steps and reads the shape's mip log2(k) (`viewStep()`/`viewStepLod()`), −9 % toward the horizon; ⚠️⚠️ every box entry is DITHERED, one inside a step included — stopping exactly on it drew contour rings on the far clouds (a mean |Δ| does not see them: ZOOM). Dead ends, measured: a pixel-footprint LOD (nothing sub-pixel before ~20 km), a directional sky ambient (identical colour, +0.6 ms; the "white blobs" are the sun, ~7:1). What tints them: `Look::skyTint` (0-1, default 0), the sky's hue over its brightest channel — `terrain` 1.0, `forest` 0. Engine `docs/caution-points.md` § *The cloud march: a distance LOD that works*.
- ⚠️⚠️ **The renderer's grab pass is RETIRED, never recreated in place** (fixed 2026-09-24): `refreshGrabPass()` destroyed it on the spot at every scene-target recreation (the act teardown included) while the blit of a scene with a refracting material was in flight — `VUID-vkDestroyImage-image-01000` at teardown. It now goes through the `DeferredDestructor`; `GrabPass::recreate()` is deleted. A GPU object a recorded command buffer may reference is retired, and a "recreate" helper that calls `destroy()` IS a destruction. Engine `docs/caution-points.md`.
- ⚠️⚠️ **A late-filed post-process occupant used to stay un-created forever** (fixed 2026-09-24: `syncSlotSelection()`'s early-out now requires `isCreated()`), and **a 3D image uploaded only its first slice** (fixed the same day in `ImageTransferOperation`: full depth copy, mip blit on three axes). Neither raised a VUID. Engine `docs/caution-points.md`.
- **Beer's law takes the WORLD thickness (fixed 2026-09-24)**: `KHR_materials_volume` = `thicknessFactor` in MESH space, `attenuationDistance` in WORLD space; the five Beer sites now read `StandardResource::volumeThicknessWorldExpression()` (× `svModelScale`, requested for every transmissive material). ⚠️ A library gem on a mesh of another size needs its thickness re-measured; keeping its attenuation distance means PHYSICAL absorption (a 2 m emerald is nearly black), stretching it keeps the library's colour (`forest`'s choice) — `Container::localFilepath(name)` + a JSON variant loaded under another name (`src/Resources/AGENTS.md`).
- ⚠️⚠️ **The active scene lock has WRITER PREFERENCE (2026-09-24)**: every exclusive section on `Scenes::Manager::m_activeSceneSharedAccess` builds an `ExclusiveAccessAnnouncement` BEFORE its `unique_lock`; `withSharedActiveScene()`/`hasActiveScene()` wait while one is announced. MSVC's `std::shared_mutex` is an SRWLOCK (not fair): the render loop stole the lock back from the woken writer and the Windows shutdown hung 24 s to 3+ min, validation ON or OFF (121 s → 1.5-1.8 s with the gate, NVIDIA and AMD). ⚠️ A re-entrant shared acquisition on the same thread is now a deadlock on EVERY OS once a writer is announced — code inside the frame uses `Core::m_frameScene`. Engine `docs/caution-points.md` § Platform-Specific.
- **LensFlare (rewritten 2026-09-24)**: the bright pass thresholds in DISPLAY units (× `FrameContext::displayExposure`, default 4) and INJECTS the analytic sun (a disc carrying the main light's illuminance × depth-probe × cloud visibility); the ghosts are Chapman's pseudo lens flare (mirrored through the centre) with each ghost weighted by (1 − dispersal·i)² and the halo by `haloIntensity` — flux conserved; `intensity` 5e-4 = the lens reflectance. ⚠️⚠️ A physical luminance in an `RGBA16F` target overflows 65 504 → inf → NaN, silently: write display units. Engine `src/Graphics/AGENTS.md` § LensFlare.
- ⚠️⚠️ **`Device::getGraphicsQueue()` ROTATES over the family's queues** (16 on NVIDIA, one per call) while the renderer keeps ONE (`Renderer::graphicsQueue()`): nothing orders two of them. Work that must see a frame goes INTO the frame's command buffer (the `FrameCapture`/RushMaker hooks) or waits on a semaphore the frame signals. **RushMaker records its copy inside the frame since 2026-09-25** (`Recorder::recordFrameCopy()` → `confirmSubmit()` → `onFrameSlotRetired()`, stop deferred while a copy is in flight): its post-present copy on a rotated queue read the image before the frame was drawn and the video stepped back 3-4 frames (19 of 260) while the screen was perfect. Detect a stale frame against k-2..k-5, not only k-1. ⚠️ `Queue::waitIdle()` holds the device-wide mutex for the whole wait (item `queue-waitidle-holds-the-device-lock`). Engine `src/Vulkan/AGENTS.md` § Synchronization, `src/Graphics/AGENTS.md` § 10, `docs/caution-points.md`.
- ⚠️⚠️ **A light colour is a unit-luminance CHROMATICITY (2026-09-25, owner)**: `AbstractLightEmitter::setColor()` / `LightSet::setAmbientLightColor()` keep the authored colour and send `Color< float >::unitLuminanceChromaticity()` (raw components, no sRGB decode); `intensity × chromaticity` = the delivered lux / cd. `color()` / `ambientLightColor()` REMOVED (`authoredColor()` / `emissionChromaticity()`): the compiler lists every reader. A channel may exceed 1 — never through a clamping `Color< float >` (the probe ambient did; fixed with its missing 1/π). RTGI now walks `rtLightCount()`, not 16 slots. ⚠️⚠️ **Point/spot falloff = windowed inverse square, ONE helper for every lane** (`Graphics/Effects/Shared/LightFalloffGLSL.hpp`, `saturate(1-(d/r)⁴)² / max(d², 0.01²)`, raster + RTGI/RTR/probes): it was LOST from `1c1d94ba` (2026-08-12) to 2026-09-25 (`max(1-(d/r)², 0)` only, and the RT lanes had been "fixed" to copy that curve — two lanes agreeing proves nothing about the law, check it against `I/d²`). Restored 2026-09-25 (owner): the demos' point/spot powers re-tuned to keep their look, actor lumens left physical.
- ⚠️⚠️ **A scene is not drawn before its first logic → render publication** (`Scene::hasPublishedStateForRendering()`, 2026-09-25): the triple buffer's render slot 0 is never written before it, and the first frame of `terrain` read every entity at the ORIGIN — 817 745 LOD-0 tree instances, 55.7 G triangles, a hung GPU on macOS/Windows. Poll `getRenderStatistics()` from the FIRST frame when a start is slow.
- ⚠️⚠️ **The render lists QUERY THE RENDERING OCTREE (2026-09-25), and each gather DE-DUPLICATES** (`AbstractEntity::markCollectedByRenderingGather()`: `OctreeSector::expand()` keeps a splitting sector's elements AND files them in the children — the first version drew every copy, 1.09 G triangles at the `terrain` spawn instead of 40.6 M, and hung the macOS/Windows GPUs): `Scene::gatherRenderingCandidates()` (frustum for the raster, a `TLASDistance` sphere for the RT list, the caster volume for the shadows, the range sphere for a cubemap), entity-level tests BEFORE the components; an entity outside the octree's bounds lives in `m_renderingOctreeOverflow`. Before, every entity × component × cascade was walked and the volume tested last (`terrain`: 9 FPS for 32 ms of GPU → 22 ms). `rebuildRenderingOctree()` transferred only the root's elements (fixed). A sector IS an `AACuboid` (`Frustum::isSeeing(box)`); the octree's doc claiming a `Frustum` overload of `isColliding()` is wrong.
- ⚠️⚠️ **The sky is depth `1.0` EXACTLY (2026-09-25)** — the clear value; the background writes no depth. Test `depth >= 1.0` / `< 1.0`, never "close to 1": the depth is conventional, `1 - depth ≈ near / z`, so `0.9999` = a camera distance of ~890 m with the 0.089 m near plane. Eight sites held one (clouds, fog, volumetric scattering, lens flare 0.99999 = 8.9 km, the god rays' `depthThreshold`, both contact shadows): the `terrain` clouds were drawn over every mountain in front of them. Engine `docs/caution-points.md` § *a sky test at `depth >= 0.9999` is a DISTANCE*.
- ⚠️⚠️ **Unproject CAMERA-RELATIVE, never through the float inverse of the FULL view-projection (2026-09-25)**: invert `projection * viewMatrix(readStateIndex, true, 0)` (the infinity view = rotation, no translation), unproject to an eye-relative offset, add the camera position afterwards. The absolute inverse distorts the whole screen by ±1-2 px at 1.3 km from the origin and ±5-13 px at 7.8 km, differently at every pose — the `terrain` clouds SLID against the relief (measured with RushMaker over `lookAt` steps: terrain 1.00-1.03× a pure-rotation model, clouds 1.46-1.71×; no frame lag). RTR, RTGI, RTAO, RTContactShadows and the GIDenoiser reconstructed their SURFACES that way (4 cm-4.4 m of error) — fixed the same day (`invRelativeViewProj`, `worldPos = camera + relativePos`); a same-pose A/B on the traced lane is identical but for the animated water (their distance-scaled biases hid it), so the dark, flat foliage of the traced lane was NOT this fix (it was the forests built UNLIT, fixed the same day). A precision defect of this kind is invisible on a screenshot: judge it in MOTION, away from the world origin.
- ⚠️⚠️ **Wayland: the render thread reads the display** (`Window::drainDisplayConnection()`, every frame) and **the swap-chain image is acquired OUTSIDE the scene lock** (`Renderer::beginFrame()` before `withSharedActiveScene()`, `renderFrame()` inside, `abandonFrame()` on shutdown) — a main thread busy loading while MAILBOX presented 13 000 frames/s filled GNOME's 1 MiB buffer, the client was DROPPED (silent GLFW close request, 60 s acquire stall, crash at exit). Every `Core::stop()` trigger is traced (`Stop requested by …`). Engine `docs/caution-points.md` § Platform-Specific.
- **Every sampled texture has a mip chain, `AnimatedTexture2D` included (2026-09-25)** — the ocean's normal map had ONE level. **The model scale is requested for EVERY transmissive material** — excluding depth-based opacity broke the ocean's refraction (`'svModelScale' : undeclared identifier`). **The clouds' shadow map sizes itself** (8 × the clouds' mean width, `ShadowCoverage` = the floor; the depth range encloses every cloud).
- **Normal maps = Khronos convention (+Y up, right-handed TBN)** — engine `AGENTS.md` axiom 5b; a Direct3D-style map is fixed in the texture, never by a shader/loader flag.
- Multiply by `environmentLuminance` only what **comes out of the cubemap**; anything read back from the rendered scene is already an absolute luminance.
- **⚠️⚠️ A `[0,1]` constant that reaches the scene colour buffer is ALWAYS a bug.** That buffer holds **absolute luminance in nits** (a 100 000 lux sun on a 0.5 albedo is ~15 900 nits), and tone mapping is downstream. An effect parameter typed as a colour is a **CHROMATICITY** and needs a luminance to go with it — the pattern is `VolumetricLight`, which reads the light's chromaticity (`mainLight->emissionChromaticity()`, unit luminance since 2026-09-25 — the former `color()` is gone) and `mainLight->intensity()` **separately**. Derive the scale when the scene does not state one: `L = E · ρ / π`, the Lambertian relation used everywhere else. ⚠️ This mistake is invisible in code review **because the numbers look like colours**: `AtmosphericFog` composited `fogColor{0.5, 0.6, 0.7}` raw for months, i.e. a 0.6-**nit** fog that replaced the sky with black (fixed `3c536623`).
- **⚠️⚠️ `Scenes::NodeCrawler` NEVER yields the BASE node**: `while (crawler.fetchNextNode()) { use(crawler.currentNode()); }` walks the base node's **DESCENDANTS ONLY** — a caller that must also process the base node does it **BEFORE** the loop (pattern in `Scene.entities.cpp`). Before the first fetch `currentNode()` IS the base node; after the last it is `nullptr`, so a loop body never sees null. **Never cache the node in a local**: a stale copy of the root compiles cleanly and runs every iteration ON THE ROOT.
- Platform: OS-specific code isolated in `src/PlatformSpecific/` via **file suffixes** (`*.linux.cpp`, `*.mac.mm`, `*.windows.cpp`), not `#ifdef` blocks in shared files.
- **Console commands are TYPED** (2026-09-27): `bindCommand(name, description, {{"param", "meaning + unit"}, …}, [this] (float x, std::optional< int32_t > n) { … return Console::CommandResult::success(…); }, Console::CommandHint::…)` — types deduced from the lambda (`bool`/`int32_t`/`float`/`std::string`/`Console::Argument`, `std::optional<T>`, trailing `std::vector<T>`), one `Parameter` per argument or it does not compile, arguments validated before the lambda runs, usage generated. The untyped `(Arguments, Outputs)` form no longer exists (deleted 2026-09-27). Out-of-range = `CommandResult::error`, never a silent clamp. Engine `src/Console/AGENTS.md` § 3 and § 7. The same applies to projet-alpha's own commands (`src/Act.cpp`).
- **Driving a component from the console / MCP** (2026-09-27): an ADAPTER per component type (`Scenes/Component/ConsoleAdapter.hpp`, lights in `LightConsoleAdapters.cpp`), never a `ControllableTrait` on the component itself; every command takes `entity, component` explicitly (no targeting state) and runs under `withExclusiveActiveScene()`. Capture ~1 s after a change (logic tick + render state). Engine `src/Scenes/AGENTS.md` § "Exposing a Component to the Console / MCP".
